# unit-done

기능 하나 = 커밋 하나 = PROMPTS.md 섹션 하나. 이 절차로 그 1:1을 지킨다. 순서를 건너뛰지 않는다.

## 1. 검증

`/verify` 실행. 모두 ✅가 아니면 여기서 멈춘다.

## 2. 사용자 diff 리뷰 (HTML)

아래에 해당하면 `git diff HEAD`를 **HTML 뷰(Artifact)로 만들어 보여주고** 사용자가 읽을 때까지 기다린다:

- 핵심 로직 변경 — mock API, 낙관적 업데이트·롤백, 상태 스토어 (크기 무관, 항상)
- 그 외 — 50줄 이상이거나 파일 3개 이상

파일별로 나누고, 왜 이렇게 짰는지 한 줄씩 붙인다. 사용자가 지적한 것은 PROMPTS.md 리뷰 항목의 재료다.

## 3. 교차 리뷰 (OCR delegate 모드)

```bash
ocr delegate preview
ocr delegate rule <이번 단위에서 바뀐 파일들>
```

받은 규칙을 기준으로 `git diff HEAD -- <파일>`을 직접 리뷰한다. 관점: 정확성·에러 처리·경쟁 상태·접근성·불필요한 복잡도.

- **High / Medium만 보고한다.** Low는 버린다.
- **자동으로 고치지 않는다.** 각 항목을 "문제 / 근거 / 제안 수정"으로 정리해 사용자에게 보여주고, 채택·수정·기각은 사용자가 정한다.
- 사용자가 채택한 항목만 수정하고 `/verify`를 다시 돌린다.

## 4. PROMPTS.md 섹션 초안

이번 단위에서 실제로 오간 대화를 바탕으로 아래 형식의 초안을 쓴다. **프롬프트는 요약하지 말고 원문 그대로.** 리뷰·검증 항목에는 실제로 발견한 것만 적는다 — 없었으면 "1차 출력 채택, X만 직접 확인"처럼 짧게.

```markdown
## [scope] 제목

### 프롬프트 1
(원문)

### AI 출력 요지
(무엇을 내놓았나 — 파일·구조·핵심 결정)

### 리뷰 / 검증
- 문제: ...
- 알아챈 방법: (직접 재현 / 테스트 / 코드 정독 / OCR 리뷰)
- 판단: 채택 / 수정 / 기각 — 이유
- 수정 내용: ...

### 판단
(이 단위에서 사용자가 내린 결정 요약)
```

사용자가 초안을 검토·수정한다. 사용자의 말로 고쳐진 것이 최종본이다.

## 5. DECISIONS.md 갱신

이번 단위에서 새로 내린 설계 결정이 있으면 한 줄씩 추가한다. 없으면 건너뛴다.

## 6. 커밋 메시지 초안

```
type(scope): 요약

- 무엇을 왜
- AI 초안에서 손본 점 (없으면 "AI 초안 그대로 채택")
```

## 7. 커밋 · push

사용자가 메시지를 확인하면 실행한다:

```bash
git add -A
git commit -m "<확인된 메시지>"
git push
```

push 실패 시 원인을 보고하고 해결한 뒤 재시도. 커밋은 되었는데 push만 실패한 상태로 두지 않는다.
